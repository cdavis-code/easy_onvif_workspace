# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/),
and this project adheres to [Semantic Versioning](https://semver.org/).

## [0.3.0]

* Credentials come from `easy_onvif`'s encrypted bundle: the Dart VM binary
  reads `ONVIF_CONFIG_FILE` / `~/.onvif/credentials.json` (plaintext files still
  work) and honours `ONVIF_DEVICE`; the Node bundle reads `ONVIF_BUNDLE` +
  `ONVIF_KEY` instead, since an `npx` process has no filesystem home.
* A credential file that exists but cannot be opened (missing key, wrong key,
  tampering) now fails with the precise remedy instead of silently falling back
  to the environment.

## [0.2.0]

* Added `--version` / `--help` to the stdio binary so `brew test` (and a human) get a
  zero-exit answer instead of a server that blocks on stdin.
* The npm tarball no longer ships `bin/easy_onvif_mcp_server.dart` (Dart source);
  `files` names the Node wrapper explicitly.
* Note: the single-package layout described under 0.1.1 ships as 0.2.0 — npm 0.1.1
  on the registry was still built from the two-package layout.

## [0.1.1]

### Changed
- Tools are now declared as `@Tool` methods on `EasyOnvifMcpServer` and the
  stdio dispatcher is generated by `easy_api_generator` + `build_runner`
  (`lib/src/easy_onvif_mcp_server.mcp.dart`), replacing the hand-written
  registry.
- The npm artifact lives in this package: `package.json`, `bin/easy-onvif-mcp.js`
  and `dist/`, built from `lib/src/js/entry.dart`. The separate
  `easy_onvif_mcp_js` package is gone. It keeps a small tool registry (the
  generated dispatcher imports `dart:io` and cannot be compiled to JS), guarded
  against drift by `test/tool_defs_test.dart`.
- `onvif_connect` no longer takes a password on the Dart VM; it reads
  `ONVIF_PASSWORD` or the credentials file. Nothing credential-shaped is ever a
  validated tool argument, so `dart_mcp` cannot echo one into the transcript.
- Tool calls are serialized through a re-entrant lock, so a handler may call
  helpers that serialize themselves without deadlocking.
- The Node.js bindings (`NodeFetchAdapter`, `NodeMulticastProbe`, `dgram`,
  JS globals) moved into `easy_onvif` and are exported from
  `package:easy_onvif/node.dart`.

## [0.1.0]

### Added
- Initial release: a stdio MCP server for ONVIF devices on top of `easy_onvif`.
- Host-agnostic tool registry (`buildOnvifTools`) shared by the Dart VM binary
  and the `npx easy-onvif-mcp` Node.js bundle via the `McpRuntime` seam.
- Connection tools (`onvif_connect`, `onvif_disconnect`, `onvif_status`) plus
  WS-Discovery (`onvif_probe`).
- Read-only device management, media, imaging, recording, replay and search
  tools, and the PTZ movement/preset set.
- Credentials from `ONVIF_HOST` / `ONVIF_USERNAME` / `ONVIF_PASSWORD` or the
  `easy_onvif_cli` `~/.onvif/credentials.json`.
- Credentials are never echoed back: `onvif_connect` opts out of `dart_mcp`
  argument validation, whose failure message quotes the rejected value, and
  validates in-handler instead (a numeric default password would otherwise be
  disclosed in the error text).
- Device-mutating operations (reboot, user management, network writes) are
  intentionally not exposed.
